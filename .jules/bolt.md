## 2025-05-23 - Property Statistics Query Consolidation
**Learning:** Found that `PropertyService::getPropertyStatistics` was making 6 separate database queries (count, where count, etc.) and suffered from a logic bug where consecutive `where()` calls on a shared query builder instance caused filters to stack (e.g., `status = 'active' AND status = 'sold'`), leading to zero results. Also discovered a schema mismatch where the code used 'available' but the database enum uses 'active'.
**Action:** Use conditional aggregation (`COUNT(CASE WHEN...)`) to consolidate multiple counts and sums into a single database query. Always clone the query builder or use `selectRaw` for multiple filtered metrics to avoid filter stacking. Verified the schema for status and column names before optimizing.
