## 2025-03-20 - [Laravel Query Builder In-place Mutation & Schema Mismatch]
**Learning:** Found a critical performance and logic bottleneck in `PropertyService`. The code was performing 6 separate queries for statistics while mutating the same Query Builder instance with `.where()` calls. In Laravel, `.where()` modifies the builder instance in-place, leading to "stacked" filters (e.g., `WHERE status='active' AND status='sold'`), which returns zero results. Additionally, the service used `'available'` status which didn't exist in the database enum (`'active'`).
**Action:** Use conditional aggregation (`COUNT(CASE WHEN ... THEN 1 END)`) to consolidate multiple counts and sums into a single database query. Always verify status strings against database migrations or model scopes to avoid silent query failures.
