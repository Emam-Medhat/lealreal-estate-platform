## 2024-03-22 - [Optimized Property Statistics and Fixed Query Mutation]
**Learning:** Found that `PropertyService::getPropertyStatistics` was performing 6 redundant database queries. More critically, the Query Builder instance was being mutated by successive `where()` calls (e.g., `$query->where('status', 'available')->count()` then `$query->where('status', 'sold')->count()`), which resulted in stacked filters (searching for both available AND sold) and incorrect zero results. Also discovered the system uses 'active' status instead of 'available' for property availability.
**Action:** Use conditional aggregation (`COUNT(CASE WHEN ... THEN 1 END)`) within `selectRaw` to consolidate multiple counts/sums/avgs into a single query. This avoids query mutation bugs and reduces database round-trips. Always verify the correct enum values for 'status' in migrations.
